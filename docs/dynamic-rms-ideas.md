# Идеи динамических RMS

Список кандидатов в коллекцию DynamicRMS. Каждая идея: суть, привязка к
API движка (с указанием апдейта DE, где появилась) и открытые вопросы.
Статус всех идей — **идея** (до ТЗ). Базис механик — FrozenLake
(аура task 155, temp-ауры, нотификации) и общая XS-библиотека, которую
стоит вынести из FrozenLake.xs (`xsAddAura`/`showLakeNotice`/таймеры) в
отдельный подключаемый файл.

Записаны идеи 2 и 3 из брейншторма 18.11.2026 (погодная семья).

## Идея 2. День/ночь (раб. название SilentWoods) — **РЕАЛИЗОВАНО**

Статус: карта собрана и проверена в игре (2026-11-21), детали и открытые
вопросы — `docs/silentwoods-review.md`; рантайм-факты — в
`knowledge/reference/dynamic-map-runtime.md`. Отличия от исходной записи:
волки — Arctic Wolf с усиленным обзором, спавн из пещер-палаток по 6 шт.,
без наведения и без деспавна (стаи копятся); пещеры = единственные
нейтральные золото/камень; фазы 5+5 минут.

**Суть.** Цикл смены дня и ночи на лесной карте: днём лес безопасен и дичь
активна, ночью экран затемняется, из чащи выходят агрессивные хищники и
охотятся за поселянами. Игрок планирует вырубку и охоту под фазу света.

**Механика по фазам.**

- День: `xsSetColorMood` — нейтральный/тёплый mood; спавн дичи
  (олени/кабаны) на свежих полянах; хищники пассивны или удалены.
- Ночь: `xsSetColorMood` — тёмный mood; периодический спавн 1–3 волков
  около случайных игроках (`xsCreateUnit`); волки со стейтом агрессивной
  gaia; звук (`xsPlaySound`) + баннер-нотификация («Ночь опускается на
  лес»); на экране таймер до рассвета (`xsDisplayTimer`).

**Привязка к API.**

| Механика | API | Появился |
|---|---|---|
| Перекраска экрана | `xsSetColorMood(colorMood, interval)` | U169123 |
| Спавн юнитов | `xsCreateUnit(objectId, playerId, location, …)` | U169123 |
| Агрессивная gaia | Capture Flag «Never (Gaia Aggressive)» | U185872 |
| Таймер фазы | `xsDisplayTimer` | U177723 |
| Нотификации/звук | `xsDisplayInstructions`, `xsPlaySound` | U177723 |

**Открытые вопросы.**

1. Список значений Color Mood (в Constants.xs из ugc-guide) — что реально
   даёт «ночь»; не пересекается ли с настройкой игрока.
2. Как заставить волков идти к поселянам: attack-move через `xsTaskUnits`
   к позиции ТС, либо агрессивный стейт сам находит цель.
3. Судьба выживших волков на рассвете: despawn (`xsRemoveUnit`) или
   остаются нейтралами (превращение через Transform task).
4. Синхронизация: все API синхронные — рассинхрона быть не должно, но
   проверить в MP с задержками.
5. Ритм фаз: наследует открытый вопрос FrozenLake (тики или секунды у
   `minInterval`).

## Идея 3. Сезонный год (раб. название FourSeasons)

**Суть.** Годовой цикл из четырёх сезонов; каждый сезон перекраивает
экономику и риски: зима душит улицы морозом, весна выгоняет дичь, лето
открывает золотой прилив, осень ускоряет сбор. Победа — успеть использовать
«свои» сезоны и не сдохнуть зимой.

**Механика по сезонам** (переключение — одно правило-оркестратор).

- Зима: морозная аура FrozenLake (−regen в радиусе озера/леса) +
  color mood; еда гниёт медленнее? (нет API — просто риск выхода к еде).
- Весна: спавн стад дичи и кустов ягод (`xsCreateUnit` на нейтральных
  точках); безопасная фаза для экспансии.
- Лето: «золотой прилив» — центральный объект с task 151 (Generating
  Resources) начисляет золото ближайшему игроку / всем поровну; мотивация
  контролировать центр.
- Осень: временная аура +work rate на gatherers (атрибут через aura) или
  task 164 (Drop off bonus) на объектах склада — «урожайная жатва».

**Привязка к API.**

| Сезон | API | Появился |
|---|---|---|
| все переключения | temp-ауры (`cAuraEffectBitTemporary` + cooldown) в `xsAddAura` | до U169 (проверено FrozenLake) |
| весна | `xsCreateUnit` | U169123 |
| лето | task 151 Generating Resources (+ Unused Flag 4 = work rate как множитель) | U185872 |
| осень | task 164 Drop off bonus / аура атрибутом | U185872 |
| UI | `xsDisplayTimer` + `xsDisplayInstructions` | U177723 |

**Открытые вопросы.**

1. Длительность сезонов и общий темп (снимается вместе с вопросом тиков).
2. Как синхронно снимать набор аур прошлого сезона и вешать новый: один
   rule-оркестратор с состоянием-счётчиком; переиспользовать
   `xsRemoveAura` по списку классов.
3. Кому идёт золото task 151 у центрального объекта: владельцу (захват —
   тянет за собой механику монумента из брейншторма) или всем.
4. Баланс: зима не должна выкашивать поселян полностью (−45 HP/s из
   FrozenLake, вероятно, слишком жёстко для длительной фазы — нужен
   щадящий множитель или укрытие у ТС).
5. Крайние размеры карт: радиусы сезонов привязать к `xsGetMapWidth()`
   (паттерн `lakeAuraRadius()` из FrozenLake.xs).

## Идея 4. Тонкий лёд (раб. название ThinIce)

**Суть.** Переправы через замёрзшее озеро — полоски льда, которые изнашиваются
от использования: частые переходы раскалывают лёд, после чего переправа
становится опасной. Редкие переходы и паузы — лёд «подмораживается» обратно.

**Ключевое решение — износ по времени контакта, не счётчик проходов.**
Дискретного события «юнит наступил на тайл» в движке нет; proximity-механики
(аура task 155, Stinger 157) работают, пока юниты в радиусе. Поэтому:

- Глыба льда — gaia-объект с HP и аурой **на саму себя** (`affectSelf` в
  `xsAddAura`, проверено): пока в радиусе есть юнит
  (`unitsInRangeToTurnOn=1`), HP капают (отрицательный `regeneration rate`);
  радиус пуст — аура деактивируется. Плюс небольшой положительный реген в
  простое («подморозка»).
- HP→0 → `ATTR_DEAD_ID` (цепочка король→саботёр из FrozenLake) → спавн
  «треснувшей» глыбы с аурой урона по всем в радиусе. Переправа остаётся
  проходимой, но опасной: «идёшь на свой страх».

**Геометрия.** Мосты — наложением lands (как кольца озера): после кольца
воды 4 диска ICYSHORE r≈6 на радиусе 28.5 (углы 45°+k·90°) перезаписывают
воду, оставляя 4 симметричные перемычки; у каждой свой `land_id`-якорь,
на нём `place_on_specific_land_id` ставит глыбу.

**Графика/синергия.** Глыба — Snow Rock (2734, U185872), треснувшая —
Mossy Rock (1967). Морозная фаза FrozenLake повышает реген глыб: зима
опасна для юнитов, но чинит переправы — погодные механики усиливают друг
друга.

**Ручки баланса** (per-глыба через `effect_amount` в RMS): HP (бюджет
«секунд контакта»), скорость дренажа, реген простоя, урон треснувшего.

**Открытые вопросы.**

1. Деактивируется ли аура при уходе юнитов из радиуса (заявлено
   `unitsInRangeToTurnOn`, проверить в игре).
2. Коллизия Snow Rock на узкой перемычке: ширина моста 4–5 тайлов или флаг
   без коллизии (искать в атрибутах).
3. `ATTR_DEAD_ID` на gaia-объекте: «треснувший» наследует позицию?
4. Стакается ли аура урона треснувшего с глобальным морозом (два
   отрицательных регена на одном юните).
5. Ремонт треснувшего: v1 — не чинится; v1.5 — сезонное пересоздание
   (`xsRemoveUnit`+`xsCreateUnit` по якорям).

**Вердикт:** v1 полностью на проверенном стеке (ауры + affectSelf +
DEAD_ID + наложение lands). Состояние «объект с износом» — универсальный
примитив для будущих карт (жилы, леса).

## Идея 5. Разрушение по цепочке (здание умерло — рушится ещё что-то)

**Статус ветки А (пороховой погреб): не делаем.** Решение 20.11.2026 —
взрывные механики уходят из коллекции; Explosive King удалён из FrozenLake.
Варианты Б (мародёрство), В (плотина), Г (инверсия) остаются идеями.

**Суть.** Смерть здания влечёт последствия за пределами самого здания:
взрыв, разрушение соседей, выброс ресурсов, затопление. Основа та же, что
у «взрывного короля»: `ATTR_DEAD_ID` при смерти юнита спавнит следующий
объект — только якорь не король, а постройки игроков.

**Варианты.**

- **А. Пороховой погреб.** Башни/замок при разрушении детонируют
  (DEAD_ID → саботёр из FrozenLake, blast radius настраивается).
  Осада становится рискованной для атакующего — сдвиг мета.
- **Б. Мародёрство.** Смерть амбара/склада выбрасывает gaia-ресурс в точке
  смерти (DEAD_ID → куча золота/еда): рейд кормит атакующего.
- **В. Плотина.** RMS оставляет перемычку-форд на реке (та же техника
  полоски, что в ThinIce) с глыбой-плотиной; разрушение плотины —
  «затопление»: спавн зоны с постоянной аурой урона на низине
  (объект-эмиттер с большим радиусом). Фильтр целей — флаги Charge Attack
  Filter (U185872): «все, кроме кораблей» = −64. Плотина = та же
  «хрупкая переправа», что тонкий лёд, но с триггером «убей», а «износ».
- **Г. Инверсия (смежная).** Здание-якорь ауры (очаг/печь): пока стоит,
  у базы игрока мороз не действует; разрушение чужого очага открывает
  его базу морозу. Не «рушится что-то», а «рушится зависимость».

**Привязка к API.**

| Механика | API | Статус |
|---|---|---|
| смерть → спавн следующего | `SET_ATTRIBUTE … ATTR_DEAD_ID` | проверено на юнитах (FrozenLake), на зданиях — нет |
| взрыв | саботёр: SET/MUL атаки, blast radius, `ATTR_BLAST_LEVEL` | конфиг из FrozenLake |
| выброс ресурса | DEAD_ID → gaia-объект ресурса | новое, правдоподобно |
| зона затопления | аура-эмиттер с фильтром классов | фильтр U185872, эмиттер проверен |

**Открытые вопросы.**

1. `ATTR_DEAD_ID` при разрушении здания уроном ( razed ), а не скриптовой
   смертью — главный вопрос ветки; заодно foundation vs готовая постройка.
2. Владение спавном: DEAD_ID на юните игрока порождает gaia (как в цепи
   короля) — проверить, что так и на зданиях.
3. Каскад: у взорванного саботёра свой DEAD_ID? (вторичное обрушение
   соседей — цепочка на 2 шага).
4. Аудио/визуал взрыва и затопления: звук события + color mood, без
   нового контента.
5. Для варианта В: восстановимость плотины (v1 — нет; v1.5 — пересоздание
   скриптом).

**Вердикт.** Вариант А собирается почти целиком из проверенного (риск —
только DEAD_ID на зданиях). Вариант В — прямой родственник ThinIce: общая
«модуль переправы» с двумя триггерами (износ / уничтожение). Для общей
XS-библиотеки это один примитив «хрупкая переправа» с конфигом.

## Идея 6. Песчаная буря (раб. название SandSea)

**Суть.** Погодный цикл на пустынной карте: с периодичностью поднимается
буря — дальность стрелков и обзор падают в открытых песках, торговцы и
лучники страдают, укрытия (оазисы, скалы) становятся ценными. Пара к
FrozenLake: там мороз душит ближний бой у воды, здесь — дистанционку
в открытом поле.

**Механика.**

- Цикл тот же, что у мороза: правило-оркестратор, temp-ауры, баннеры,
  таймер «до бури».
- Аура на зону песков: отрицательные атрибуты на классы лучников/конных
  лучников/верблюдов; торговцы (cTradeCartClass) — в ту же ауру.
- Атмосфера: `xsSetColorMood` (желтизна/мутность), `xsPlaySound` ветер.
- Оазисы-«карманы» с пальмами как естественные укрытия (RMS-генерация).

**Привязка к API.**

| Механика | API | Статус |
|---|---|---|
| дебафф аурой | task 155 `xsAddAura` (паттерн FrozenLake) | проверен |
| −обзор / −дальность | аура атрибутов `ATTR_LINE_OF_SIGHT` / `ATTR_MAX_RANGE` | **не проверено** — «not all attributes supported by auras» |
| атмосфера | `xsSetColorMood` (U169123), `xsPlaySound` (U177723) | документировано |

**Открытые вопросы.**

1. Поддерживают ли ауры ATTR_LINE_OF_SIGHT и ATTR_MAX_RANGE — выяснить
   пробным правилом до ТЗ; если нет — деградировать на «урон по времени»
   (как мороз) + уменьшение скорости.
2. Атмосферный mood меняется у всех синхронно? (чистый UI, должен).
3. Радиус зоны песков на карте без озера — генеральная привязка к
   `xsGetMapWidth()`.

**Вердикт.** Собирается на стеке FrozenLake с одним неизвестным (п. 1).
Первый кандидат на «вторую погоду» — доказывает, что погода в коллекции
система, а не фича одной карты.

## Идея 7. Спорный монумент (раб. название MonumentWars)

**Суть.** В центре карты нейтральный монумент: игрок, чьи юниты держат
зону вокруг него, захватывает объект (`xsSetUnitOwner`) и получает поток
ресурсов, пока владеет. Постоянный магнит для армии, анти-черепаха.

**Механика.**

- Скрипт-сканер (rule, раз в ~1 с): для каждого игрока считать юнитов в
  радиусе R от монумента; если ровно один игрок держит зону N секунд
  подряд — захват (`xsSetUnitOwner(monument, player)`).
- Доход владельцу: task 151 (Generating Resources, U185872) на монументе
  после захвата; при смене владельца пересоздать таск.
- Индикация: баннер при захвате/потере, `xsSetUnitCaption` (U185872) —
  «удерживается игроком N», таймер захвата на экране.
- Debounce: смена владельца только после полного опустения зоны (или
  таймер перезахвата).

**Привязка к API.**

| Механика | API | Статус |
|---|---|---|
| смена владельца | `xsSetUnitOwner(unitId, playerId, flashUnit)` (U185872) | документировано |
| перечисление юнитов | `xsGetPlayerUnitIds` + массивы; позиции `xsGetUnitPosition`, `dist()` (U169/U177/U185) | **узнать точные сигнатуры** |
| доход | task 151 + Unused Flag 4 (U185872) | документировано |
| подпись объекта | `xsSetUnitCaption` (U185872) | документировано |

**Открытые вопросы.**

1. Точный вид API перечисления юнитов игрока (array ID, перезапуск
   массива), цена вызова в rule раз в секунду.
2. Монумент как gaia-здание: не мешает ли юнитам стоять в радиусе
   (коллизия), видно ли его в тумане (нужен LOS-маяк рядом — паттерн
   аутпостов FrozenLake).
3. Перезахват: мгновенный или с таймером «сопротивления».
4. Баланс дохода: сколько золота/мин делает точку «стоящей армии».

**Вердикт.** Самая новая механика класса «захват» — главный дифференциатор
коллекции. Блокер один: API перечисления юнитов — общий с идеями 8 и 9,
исследуется один раз для всех.

## Идея 8. Волны мародёров (раб. название RaiderShore)

**Суть.** Каждые N минут от краёв карты к игрокам идёт волна gaia-мародёров;
сила волн растёт по таймеру. Карта сама давит на темп: нельзя тихо
фармиться в угол.

**Механика.**

- Спавн: `xsCreateUnit` (U169123) пачкой у точки-якоря на краю; агрессивный
  gaia (Capture Flag «Never (Gaia Aggressive)», U185872) сам находит цели —
  либо приказ attack-move `xsTaskUnits` к ТС игрока.
- Эскалация: счётчик волн в XS; каждой волне — бафф HP/атаки
  (`effect_amount` по ID из `xsCreateUnit`).
- Информирование: баннер «Волна 3 идёт с востока», `xsDisplayTimer` до
  следующей.
- Награда: мародёры с task 161 (Unit Refund)? или просто трофеи-ресурсы.

**Привязка к API.**

| Механика | API | Статус |
|---|---|---|
| спавн с получением ID | `xsCreateUnit` → int unitId (U169123) | документировано |
| агрессивная gaia | Capture Flag (U185872) | документировано |
| приказ на точку | `xsTaskUnits(unitIds, actionType, location, …)` (U185872) | документировано |
| бафф по ID | `xsEffectAmount` по unitId | паттерн проверен |

**Открытые вопросы.**

1. attack-move в `xsTaskUnits`: какой actionType; надёжность aggro у gaia.
2. Спавн в тумане: видят ли юниты цели из «чёрной» зоны; не застревают ли
   о лес (генерация спавна в просветах).
3. Производительность на поздних волнах (сотни юнитов) — ограничить
   размер волны/частоту.
4. Fairness: волна бьёт всех сразу или ближайшего (последнее — спортивнее).

**Вердикт.** Всё документировано, риска только в балансе и поведении aggro.
Хорошая карта для отработки спавна — примитив пригодится идеям 9 и 3.

## Идея 9. Приливы ресурсов (раб. название Tides)

**Суть.** Ресурсы «дышат»: косяки рыбы подходят и уходят, стада мигрируют,
жилы золота истощаются со временем. Карта требует постоянного расширения.

**Механика.**

- Косяки: периодический спавн SHORE_FISH у берега (`xsCreateUnit` в точке,
  проверенной `xsGetMapTileAttribute` — вода?), деспавн по таймеру
  (`xsRemoveUnit`).
- Миграция стад: десень/кабаны периодически пересоздаются в новой точке
  (remove старых — create новых).
- Истощение жил: раз в N минут скрипт удаляет по одному юниту-золоту из
  каждой пачки (`xsRemoveUnit`) — жилы «осыпаются».

**Привязка к API.**

| Механика | API | Статус |
|---|---|---|
| спавн/удаление | `xsCreateUnit` / `xsRemoveUnit` (U169123) | документировано |
| проверка тайла | `xsGetMapTileAttribute(x, y, attr)` (U185872) | документировано |
| перечисление объектов пачки | перечисление юнитов (как в идее 7) | **узнать сигнатуры** |

**Открытые вопросы.**

1. Перечисление gaia-объектов по классу (золото/рыба) — та же задача, что
   у монумента.
2. Удаление куска жилы: игроки увидят «исчезнувшее» золото — как подать
   (баннер «жилы истощаются») и не ломает ли AI-экономику
   (`ai_info_map_type`).
3. Миграция стад: деспавн стада под охотником — резко; нужен «уход»
   (приказ движения) или хотя бы предупреждение.

**Вердикт.** Реализуемо, экономно по API; главные риски — UX (не бесить
игрока) и совместимость с AI. Хороший «средний» кандидат после монумента.

## Прочие наброски (не развёрнуты)

- **Метеорный дождь**: gaia-саботёры детонируют в случайных точках —
  зрелищно, дёшево (весь стек FrozenLake), но слабый геймплей без привязки
  к зоне.
- **Голодные хищники**: агрессивные волки гонятся за расселившимися
  поселянами (спавн + Capture Flag) — подмножество идеи 8.
- **Перемирия**: `xsSetDiplomacy` (U169123) мирит всех на окна N минут —
  меняет темп FFA; проверить, разрешает ли движок принудительную смену
  дипломатии игроков без рассинхрона.
- **Сигналы ИИ**: `xsSetAiSignal` (U185872) — ИИ узнаёт о фазах; отдельная
  работа с .ai-скриптами, отложить до зрелости коллекции.
- **Дань-сборщик**: gaia-юнит собирает налог у ТС (Task 161 наоборот) —
  спорная фича, вынести в качество опции какой-нибудь карты.

## Общее для всех идей

- Общая XS-библиотека: ауры, нотификации, таймеры, оркестратор фаз,
  примитив «объект с состоянием/износом», примитив «хрупкая переправа» —
  один файл, подключаемый `#includeXS`; FrozenLake рефакторится на неё
  первой.
- **Сквозное исследование для идей 7/8/9** — примитивы перечисления:
  `xsGetPlayerUnitIds` (массивы, перезапуск), `xsGetUnitPosition`,
  `xsGetMapTileAttribute`. Один пробный скрипт закрывает блокер трёх идей
  сразу; сделать до выбора следующей карты.
- Проба для идеи 6: поддерживают ли ауры `ATTR_LINE_OF_SIGHT` /
  `ATTR_MAX_RANGE` (одно правило с `xsAddAura` на собственный юнит).
- Нотификации и таймеры обязательны: игрок должен читать цикл с экрана.
- Все механики синхронные — MP-совместимость по построению, но каждую
  карту всё равно проверять в лобби (правило коллекции).
- Идея 4 и вариант В идеи 5 — один модуль: переправа на полоске земли с
  объектом-стражем; различаются только триггером поломки (износ / смерть).
- Рекомендуемый порядок: пробы (сканер + аура-атрибуты) → MonumentWars
  (самая новая механика) → SandSea (вторая погода) → RaiderShore →
  Tides; ThinIce и разрушение-по-цепочке — модули-дополнения, хорошо
  ложатся на любую карту из списка.
