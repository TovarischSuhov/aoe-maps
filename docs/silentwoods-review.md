# SilentWoods — состояние и открытые вопросы

Статус: в игре проверено (2026-11-20/21, Tiny/2p, фазы ускорены до 20 с для
тестов — в релизе 300 с). LSP-гейт: `SilentWoods.rms` / `SilentWoods.xs` —
0 диагностик, кроме известных U185872-символов (`xsSetUnitProperty`,
`xsGetUnitProperty`, `cUnitVisibility`, `cUnitSelectable` — верифицированы по
changelog/ugc-guide).

## Что это

Идея 2 из `docs/dynamic-rms-ideas.md` («день/ночь», раб. название SilentWoods).
Открытая лесная карта: старты на холмах (`base_elevation 3`) со стандартным
набором ресурсов, лес пятнами (`land_percent 20`, 20 кластеров) — экспансия
через пещеры. Нейтрального золота/камня на карте нет: на игрока приходится
**три пещерных холма — две золотые и одна каменная пещеры** (тёмная шапка
DIRT, скала, пачка 3 тайла) плюс **домашняя пещера** — скала у дальнего
золота (22–28 тайлов). Нейтральные олени: `DEER_GROUPS` пачек по 4 на игрока.
Реликвии: `3 + PLAYER_COUNT` по аравийским дистанциям.

**Механика дня/ночи:** правило `dayNightCycle` (интервал 300 с) переключает
`xsSetColorMood(Night/Default, 2)` с баннерами через `xsDisplayInstructions`
(паттерн FrozenLake). В начале ночи `SpawnWolves` перечисляет гаia
(`xsGetPlayerUnitIds(0, -1, -1)`), отбирает **якоря-палатки** (`ARMY_TENT`,
dat-тип 80 — единственные гаia-здания на карте) и спавнит по
`cWolvesPerCave=6` арктических волков (1965) рядом с каждой. Волкам через
`GAIA_SET_ATTRIBUTE ARCTIC_WOLF ATTR_LINE_OF_SIGHT 12` поднят обзор;
наведение скриптом не делается — работает врождённый predator AI.
**Деспавна нет**: стаи копятся от ночи к ночи.

## Применённые решения (2026-11-20/21)

- **Якоря — палатки, не маркеры.** Перебраны: невидимые подложки
  `PLACEHOLDER_GENERIC` (1902 — рендерится «крестьянином», 1543 — тоже
  виден; сбиваются в кластеры из-за `find_closest`), скалы (tree-class —
  не перечисляются), вышки (работают, но пользователь просил заменить) →
  финал: `ARMY_TENT` (проверенный в FrozenLake объект, тип 80).
- **Скан якорей по dat-типу, не по id/классу.** Фильтр по object id внутри
  `xsGetPlayerUnitIds` не работает (скала → `-1`); класс читается
  (`xsGetUnitClass`), но фильтрация по типу 80 — единственный проверенный
  путь. Инвариант: гаia-здания на карте = только наши палатки.
- **Wolf = Arctic Wolf (1965).** Классический `WOLF`/124 через
  `xsCreateUnit` даёт поселяноподобный юнит («крест»). LOS-буст переведён
  на `ARCTIC_WOLF`.
- **Гейтинг пещер по тройкам** (`P_C6..P_C24`, кумулятивные флаги от
  `_PLAYER_GAME`): в RMS-условиях нет сравнений. Дистанция между холмами
  12 (холмы с зонами: `zone`+`land_id` в паре — без зон
  `other_zone_avoidance_distance` не работал, холмы сливались).
- **Пачки и маркеры — `terrain_to_place_on DIRT` + без `find_closest`:**
  шапки холмов — единственная DIRT на карте (косметический DIRT убран),
  это держит объекты на холмах; `find_closest` стаскивал их в кластеры
  и тянул на чужие холмы.
- **Домашняя палатка** — в `actor_area 402`, который резервирует скала
  (здания области уважают; для scenery-приёмника actor area не работает).
  `set_gaia_unconvertible` обязателен: без него монк конвертирует башню.
- **Взрывные механики удалены из коллекции**: Explosive King вычищен из
  FrozenLake (см. `docs/frozen-lake-review.md`), ветка А идеи 5 закрыта.

## Проверено в игре (факты для базы знаний)

1. `rule minInterval` меряется **секундами** (20-секундный тест дал
   ~20-секундные фазы).
2. `xsSetColorMood` рендерится только при включённой настройке графики
   **«Коррекция цвета» (Map lighting)**; `cColorMoodNight` работает,
   `cColorMoodDarkness` не проверен.
3. `second_object` ставит объект **поверх** основного (не чередует).
4. **Tree-class объекты не перечисляются** `xsGetPlayerUnitIds` (деревья,
   скалы): `gaiaAll` считает только «настоящие» юниты.
5. `ignore_terrain_restrictions` обязателен для tree-class scenery при
   `set_place_for_every_player` — иначе молчу не ставятся.
6. `actor_area`/`actor_area_to_place_in`: работает для юнитов и зданий,
   не работает со scenery в роли принимающего.
7. Игровой парсер XS: переменные **function-scoped** (ошибка 0014),
   `vector()` принимает только литералы (0340; динамические —
   `xsVectorSet`), `else if` (не `elseif`).
8. `xsGetPlayerUnitIds(playerId, objectOrClassId, arrayId)`: порядок по
   ugc-guide; третий аргумент — переиспользование существующего массива,
   не созданного → передавать `-1`. Чаглог (строка 284) врёт про порядок.
9. Классы (ugc-guide prelude): 907 кусты, 908 камень, 909 кабаны,
   910 хищники, 911 прочее, 929 овцы, 932 золото, 942 реликвии,
   915 деревья; `xsGetUnitType` возвращает dat-категорию (10 EyeCandy,
   30 Moving, 80 Building), не object id.
10. ID юнитов для `xsCreateUnit`: Arctic Wolf 1965; 124 — не волк.

## Открытые вопросы

1. **Баланс накопления**: 6 волков × (3 пещеры + 1 домашняя) = 24 волка
   на игрока за ночь при фазах 5+5. Проверить темп на 300 с и решить,
   нужен ли потолок общего числа живых волков.
2. **Лобби-проверка** (правило коллекции): мод у всех игроков лобби,
   синхронность mood/спавна при задержках.
3. **Арктический волк в умеренном лесу** визуально белый — если
   мешает, найти ID серого волка (в KB численно не подтверждён).
4. **Невидимость якорей**: `cUnitVisibility` (property 12) применился
   (`xsGetUnitProperty` читает 0), но на рендер не влияет; значения 2
   и 0 не скрыли палатку. Бэклог: doppelganger-атрибут 188, BLANKOBJECT
   (zetnus 6157), явные координаты.
5. **Тент блокирует тайлы** (здание) — точки у пещер незастроиваемы;
   приемлемо ли.

## Возможные дальнейшие шаги

- Вынести общую XS-библиотеку коллекции (`#includeXS`-файл: баннеры,
  оркестратор фаз, скан якорей по типу) — FrozenLake рефакторить первым.
- Ночной дебафф-аура (Идея 6-стайл) поверх цикла — ауры уже в стеке.
- `xsPlaySound` для смены фаз (имена звуков не подобраны).
- Потолок живых волков (`cWolvesPerCave` → счётчик при накоплении).
